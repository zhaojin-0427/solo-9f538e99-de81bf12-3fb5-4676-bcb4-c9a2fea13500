# 药品稳定性试验 · 数据文件登记与追溯平台

药品稳定性试验的数据工程师发现一份**原始测量 CSV** 有误，需要阻止建模组继续使用
由它派生的**清洗表**和**批次汇总**。本平台用 Flask + SQLite 实现三类 CSV 文件的
登记、依赖追溯、撤销级联与下载资格控制；并支持把两位工程师对同一份清洗表的
独立更正做**按键三方合并**，产出带血缘登记的新清洗表。

## 1. 需求与实现对照

| 需求 | 实现方式 |
| --- | --- |
| 上传原始测量 / 清洗表 / 汇总 CSV | 首页表单选择类型上传，仅接受 `.csv`，服务端做 CSV 结构校验（编码、表头、列数、空行） |
| 后两类登记准确父文件 ID | 清洗表、批次汇总必须填父文件 ID（支持空格/逗号分隔、多个父项）；原始测量禁止填父项 |
| 父项提交时必须可用 | 父项存在、自身未撤销、且所有祖先未撤销；检查在 `BEGIN IMMEDIATE` 写锁内完成 |
| 文件与依赖一经登记不可改 | 仅提供上传/撤销/下载/查看路由，无编辑删除接口；对象存储文件以 ID 命名且从不覆写；依赖表有主键与外键约束 |
| 撤销后直接/间接依赖立即停止下载 | 下载时递归 CTE 实时计算祖先撤销状态，撤销只置标志位，派生文件立刻被阻断，无需批量改动 |
| 页面列出受影响链 | 文件详情页用递归 CTE 列出全部下游路径（`A -> B -> C`）与受影响文件数；首页列出阻断来源 |
| 修复件使用新 ID，旧派生件不恢复 | ID 按类型自增（`RAW-0001`/`CLN-0001`/`SUM-0001`），修复上传必为新 ID；资格由不可变登记数据 + 撤销标志实时推导，旧文件不会因新上传而恢复 |
| 上传与撤销交错，不能发布引用已撤销父项的文件 | 所有写事务用 `BEGIN IMMEDIATE` 串行化，父项检查与登记在同一事务同一锁内，并发下要么拒绝上传、要么登记后子文件立即不可下载 |
| 写盘或登记失败不暴露半成品 | 先写私有暂存目录，校验通过后 `rename` 进对象存储，再提交事务；任何异常回滚并清理暂存/孤立文件；启动时清扫残留 |
| 重启后下载资格一致 | 资格完全由 SQLite 持久数据推导，无内存状态；重启后结果不变；启动清扫不触碰已登记对象 |
| 网页选择基表与两份更正表建合并草稿 | `/merge` 选择一份清洗基表 + 两份**仅以它为父项**的清洗表；服务端校验三者均为可用清洗表、列名一致、每表 ≤500 行、记录号列非空且唯一 |
| 按键逐格三方合并 | 按记录号对齐（基表顺序 → 左表新增 → 右表新增），单元格按**原字符串**比较；缺行（行不存在）与空字段（空字符串）严格区分 |
| 自动合入规则 | 单边改动取改动侧；双方相同改动直接取；双方改动落在不同单元格自动并合；一侧删除另一侧未动则删除；双方均删则删除 |
| 人工冲突处理 | 同格异改逐格选左/右；删改冲突（一侧删行、一侧改行）选保留修改行或删除；页面单选框提交，服务端按冻结的冲突清单白名单校验 |
| 草稿可续、未解完不能确认 | 草稿（合并状态 + 选择 + 修订号）存 SQLite，刷新/重启后继续；确认时仍有未解决冲突则拒绝（选择仍会保存） |
| 保存、确认均带所见修订 | 两个表单都携带隐藏 `revision`；服务端比较当前修订号并以条件 `UPDATE` 兜底，过期请求拒绝 |
| 确认生成新 ID 清洗 CSV | 成品为 `CLN-xxxx`，无保留行时仅含表头；以**左右两表**为父项登记，草稿同事务标记完成；完成后不能再改 |
| 同修订并发/重复确认返回同一文件 | 确认全程在 `BEGIN IMMEDIATE` 写锁内，先到者登记成品并完成草稿，后来者看到 `completed` 直接返回同一 `result_id` |
| 任一来源不可用则拒绝确认 | 确认前在写锁内复查基表/左表/右表可用性（自身撤销或祖先阻断均拒绝），草稿保持可重试 |
| 合并失败/中断不留半成品 | 成品先写 `.merge-` 暂存、`rename` 提升、登记与完成草稿同一事务；异常回滚并清理，启动清扫 `.merge-` 残留与未登记孤立文件；沿用血缘撤销规则与原上传校验（成品允许仅表头） |
| 可实际启动的 Docker Compose | `docker compose up --build` 一键启动，数据持久化在命名卷 `stability_data` |
| 浏览器操作入口 | 纯服务端渲染 HTML（无外部 CDN 依赖），访问 `http://localhost:8000/`，页首导航进入“三方合并” |

## 2. 目录结构

```

```

## 3. 启动方式

### 3.1 Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000/
```

- 容器内 gunicorn：1 worker × 8 线程（SQLite 单写者模型下足够，且写事务已串行化）。
- SQLite 数据库、对象存储、暂存目录均在命名卷 `stability_data`（容器内 `/data`），
  容器重建后数据、合并草稿与下载资格保持不变。
- 生产环境请通过环境变量覆盖 `SECRET_KEY`。

### 3.2 本地直接运行

```bash
pip install -r requirements.txt
python -m flask --app wsgi:app run --host 0.0.0.0 --port 8000
# 或：gunicorn --bind 0.0.0.0:8000 wsgi:app
```

数据默认写入工作目录下的 `data/`，可用环境变量 `DATA_DIR` 覆盖。

## 4. 浏览器操作流程

### 4.1 登记、撤销与修复

1. 首页“登记上传 CSV 文件”卡片：
   - 类型选**原始测量**，父文件 ID 留空，选择 CSV → 校验并登记，得到 `RAW-0001`。
   - 类型选**清洗表**，父文件 ID 填 `RAW-0001`，上传后得到 `CLN-0001`。
   - 类型选**批次汇总**，父文件 ID 填 `CLN-0001`，上传后得到 `SUM-0001`。
2. 任一文件行点“详情”：查看元数据（大小、SHA-256、时间）、直接父/子文件、
   以及“撤销影响链”中列出的全部下游路径。
3. 质控员在详情页填写撤销原因并确认：
   - 被撤销文件与其全部直接/间接派生文件的“下载”立即变为停用；
   - 页面显示完整受影响链与阻断路径。
4. 修复时重新上传修正后的原始测量，系统分配**新 ID**（如 `RAW-0002`）；
   基于新 ID 登记的新清洗表可正常下载，旧 `CLN-0001`/`SUM-0001` 维持停用。
5. 任何对已撤销/被阻断父项的新登记都会被拒绝并在页面顶部提示原因。

### 4.2 三方合并两人独立更正

1. 先按 4.1 登记：基表 `CLN-0001`（父项为某原始测量），两位工程师各自更正后
   以 `CLN-0001` 为**唯一父项**登记左表 `CLN-0002`、右表 `CLN-0003`。
2. 页首导航进入“三方合并”：选择基表/左表/右表，填写记录号列名（如 `记录号`），
   创建草稿 `MRG-0001`。列名不一致、超过 500 行、记录号为空或重复、
   左右表并非仅以基表为父项等情况都会被拒绝并说明原因。
3. 草稿页顶部显示三份来源表的实时可用性；中部逐条列出冲突：
   - **同格异改**：展示基表/左表/右表三值（缺行显示“（缺行）”、空字段显示“（空）”），
     单选“采用左表 / 采用右表”；
   - **删改冲突**：展示基表行与修改侧整行，单选“保留修改行 / 删除该行”。
   底部“自动合入明细”可展开查看每一行的自动处理依据。
4. 随时点“保存选择（草稿）”：选择落库、修订号 +1，刷新或重启后继续；
   页面修订号过期（他人在此期间保存过）会被拒绝并提示刷新。
5. 全部冲突选完后“确认合并并登记成品”：
   - 仍有未解决冲突 → 拒绝（已选内容仍会保存）；
   - 任一来源表此时已不可用 → 拒绝，草稿保持可重试；
   - 成功 → 生成新 `CLN-xxxx`（父项为左右两表），草稿锁定，
     页面提供成品下载；重复确认返回同一文件。
6. 成品沿袭平台血缘规则：撤销左表或右表，成品下载立即被阻断。

## 5. HTTP 路由

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 上传表单、文件清单（含状态徽章）、审计事件 |
| POST | `/upload` | 校验并登记 CSV（multipart：`kind`、`file`、`parent_ids`） |
| GET | `/files/<id>` | 文件详情、父子关系、撤销影响链、撤销表单 |
| POST | `/files/<id>/revoke` | 质控员撤销（必填 `reason`），幂等 |
| GET | `/files/<id>/download` | 资格通过才返回附件，否则重定向回详情并提示 |
| GET | `/merge` | 合并草稿列表 + 新建草稿表单（选基表/左表/右表/记录号列） |
| POST | `/merge` | 校验三表并创建草稿（冻结合并状态） |
| GET | `/merge/<id>` | 合并工作台：冲突处理、自动合入明细、成品下载 |
| POST | `/merge/<id>/save` | 保存冲突选择（表单：`revision`、`choice-<n>`） |
| POST | `/merge/<id>/confirm` | 应用本页选择并确认登记成品（幂等，同修订并发返回同一文件） |

## 6. 数据模型要点

- `files`：文件 ID、类型、原始文件名、SHA-256、大小、对象存储名、撤销标志/时间/原因。
- `dependencies`：`(child_id, parent_id)` 有主键、外键和 `child <> parent` 约束，
  边一旦插入不可修改。
- `id_seq`：按类型的自增序列，`UPSERT ... RETURNING` 在写事务内分配 ID，进程安全。
- `audit_events`：上传/撤销/合并审计。
- `merge_drafts`：合并草稿。`state_json` 冻结建稿时从三份源表算出的逐格合并状态
  （源文件一经登记不可变，因此状态永远有效）；`choices_json` 存冲突选择；
  `revision` 乐观并发控制；`status`/`result_id` 标记完成与成品。
  草稿随 SQLite 持久化，刷新、重启均可续作。
- 递归 CTE 分别实现祖先阻断查询（含路径）与下游影响链枚举。

## 7. 自测

```bash
python -m pytest tests/ -q
```

覆盖内容（57 个用例，全部通过）：

- 三类文件链式登记与 ID 规则；修复件新 ID、旧派生件不恢复；
- 父项缺失/已撤销/被祖先阻断/原始文件带父项等拒绝路径；
- 撤销级联后三者立即停下载、影响链与阻断路径展示、撤销需填原因、重复撤销幂等；
- 菱形依赖下任一祖先撤销即阻断；
- 坏 CSV（空文件、仅表头、列数不一致、空行）与非 `.csv` 拒绝，且失败后
  对象存储、暂存目录、数据库均无半成品；
- 不存在任何编辑/删除路由，依赖边重复插入被数据库拒绝；
- 多线程**上传与撤销交错**（屏障同步 + 15 轮重复）：不存在“引用已撤销父项且
  仍可下载”的文件；
- 模拟进程重启（同数据目录新建应用实例）：下载资格完全一致，暂存残留被清扫、
  已登记对象字节不变；
- **三方合并**：建稿校验（类型、父项唯一性、列名、500 行、记录号非空唯一、
  来源可用性）；单边/双方相同/异格改动自动合入；同格异改选左选右；
  删改冲突保留或删除；缺行与空字段有别；双方新增一致/不一致；
  无保留行时成品仅表头；草稿保存后重启续作；过期修订的保存与确认均被拒绝；
  未解完不能确认；确认登记新 ID（父项为左右两表）并锁定草稿；
  同修订并发确认与重复确认返回同一文件；来源撤销后拒绝确认；
  成品沿袭血缘撤销规则；确认中途崩溃的暂存/孤立文件重启被清扫、草稿可重试；
  浏览器全链路（选表 → 处理冲突 → 确认 → 下载成品）。

此外在 gunicorn（1 worker/8 线程）上做过真实 HTTP 端到端验证：上传链、
撤销级联、重启保持、修复流程、HTTP 并发交错，以及合并全流程（建稿、保存、
重启续作、过期拒绝、确认、下载、6 路同修订并发确认仅登记一份成品）均通过。

## 8. 已知限制（如实说明）

- 当前沙箱环境没有 Docker daemon，Dockerfile/compose 已做静态与等效流程验证
  （本地以 gunicorn + 相同入口命令跑通），但未在本环境实际执行 `docker build`。
- 平台未做用户登录与角色鉴权，“质控员撤销”是页面操作语义而非权限系统；
  如需多用户，应在反向代理或应用层补充认证。
- gunicorn 配置为单 worker 以契合 SQLite 单写者模型；读请求可通过多线程扩展，
  超高写入场景建议更换为 C/S 数据库。
- 三方合并按记录号对齐，不处理“同一记录在两表中记录号不同”的改名场景；
  列名按名称对齐（顺序可不同），成品列顺序以基表为准。
